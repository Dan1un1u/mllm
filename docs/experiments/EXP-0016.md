# EXP-0016 — QHPI sequential HMX-HVX-HMX GQA core

## Hypothesis

One QHPI_RESOURCE_HMX node can safely execute integer HMX, HVX, and integer HMX sequentially inside its main-control callback, keep intermediates in VTCM with zero core-attributed DRAM, and preserve the single-node QNN/mllm integration boundary.

## Primary physical variable

Replace EXP-0015 resource-exclusive multi-callback scheduling with one QHPI_RESOURCE_HMX callback; keep QAIRT 2.49, V79, asymmetric U8 contracts, one custom graph node, zero-DRAM placement, model scope, and comparator protocol fixed.

## Hard gate

Stage A must execute one in-graph sequential HMX-HVX-HMX QHPI_RESOURCE_HMX node on PJZ110 with byte-exact device output, true integer-HMX evidence, custom-core DRAM read-write 0-0, context ddrTensorSize 0, no spill-fill, fallback, or graph split. Any Stage A failure stops before GQA. Only after Stage A passes may Stage B implement the same layer-14 s32 context-1024 one-group GQA scope as EXP-0015, whose equivalent-scope median device wall latency must be no slower than native before expansion.

## Candidate architecture

- Register the Stage-A node with `QHPI_RESOURCE_HMX`, not
  `QHPI_RESOURCE_EXCLUSIVE`. QAIRT 2.49/V79 invokes the non-self-sliced HMX
  kernel through the main-control callback, as proven by EXP-0014.
- Issue both HMX tiles and the intervening HVX SIMD work sequentially from
  that one callback. No inter-resource phase protocol or QHPI sync block is
  permitted.
- Reuse source-destructive TCM inputs and the output crouton for staging. The
  first candidate may test an in-place second HMX store. If HMX input/output
  aliasing is rejected, a TCM-only alias-safe refinement is allowed inside
  Stage A; DDR workspace, graph split, or a second custom operator is not.
- Retain the guarded EXP-0015 resource-audit builds only as diagnostics. The
  formal gate must use the regular sequential implementation.

## Staged execution

1. **Stage A — sequential-resource gate.** Compile and execute the fixed tile;
   require bit-exact target output for identity, signed-permutation, and
   structured inputs, true integer-HMX Optrace/disassembly evidence, context
   `ddrTensorSize=0`, custom-node DRAM `0/0`, and no spill/fill/fallback/split.
   Stage A has no speed threshold.
2. **Stage B — one complete GQA group.** Only after Stage A passes, implement
   the fixed EXP-0015 layer-14 group and require equivalent-scope median device
   wall latency no slower than native. Work/active cycles remain explanatory.
3. **Expansion.** Middle-layer and full-model integration remain gated exactly
   as in EXP-0015 and do not automatically promote a baseline.

## Outcome

Completed as a valid negative result on 2026-08-25. The selected W4A8
baseline and all comparator roles remain unchanged.

### Stage A

- Source checkpoint: `a1ea2dd38d471e7741a109031ef431ff5c3c90b2`.
- The single `QHPI_RESOURCE_HMX` callback executed the required sequential
  integer-HMX, HVX, integer-HMX chain on PJZ110.
- Device output was byte-exact for the declared Stage-A cases, the custom core
  reported DRAM read/write `0/0`, context `ddrTensorSize=0`, and no
  spill/fill, fallback, or graph split was observed.
- Stage A passed, authorizing Stage B.

### Stage B

- Final source commit: `248f257754b976b329c080b808a79ad784b167dd`.
- Scope: Qwen3 layer 14, prefill `s32`, context 1024, first GQA group with two
  query heads and one shared K/V head.
- The candidate fused QK, mask/scale, SIMD Softmax, and AV inside one custom
  HMX callback. DSP disassembly and Optrace show distinct integer-HMX QK and
  AV sequences.
- The custom core passed the physical placement gate: DRAM read/write `0/0`,
  context `ddrTensorSize=0`, no spill/fill, fallback, graph split, or
  score/probability DDR tensor. Peak VTCM was `2695168` bytes.
- Equivalent-scope median device wall latency was `3634.531 us`, versus
  `124.713 us` for native QNN. The candidate was `29.143x` slower, so the
  blocking Stage-B speed gate failed.
- The non-blocking W4A16 diagnostic also failed: custom W4A8 versus native
  W4A16 had RMS-normalized NRMSE `1.002974` and cosine `0.052250`; native W4A8
  versus native W4A16 had NRMSE `0.059673` and cosine `0.998250` on the same
  independently encoded real inputs.

The zero-DRAM constraint therefore did not expose a faster path. The custom
callback serialized dynamic K/V packing, 128 QK HMX calls, Softmax, and 16 AV
HMX calls, while native lowering retained fine-grained compiler scheduling and
HMX/HVX overlap. Stage C and full-model integration were not started.
