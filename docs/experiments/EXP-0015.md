# EXP-0015 — QHPI fused GQA QK-Softmax-AV core

## Hypothesis

A single QHPI resource-exclusive GQA core can execute asymmetric-U8 QK and AV on integer HMX, perform dynamic K/V packing and scale-mask-Softmax on HVX, keep core intermediates in VTCM with zero core-attributed DRAM, and reduce equivalent-scope prefill wall latency versus the selected native W4A8 baseline.

## Primary physical variable

Replace one middle-layer s32 GQA group native split QK, scale, mask, Softmax, and AV subgraph with one fused QHPI core while keeping model weights, QKV projections, QK Norm, RoPE, cache update, head concat, o_proj, shapes, external asymmetric-U8 qparams, QAIRT, hardware, and runner protocol fixed.

## Hard gate

Stage A must prove one in-graph HMX-HVX-HMX QHPI core with true HMX QK and AV, core-attributed DRAM read-write 0-0, no spill-fill, fallback, or graph split, and exact device agreement with the declared bit-exact implementation reference. Stage B must implement layer 14 s32 context 1024 for one two-query-head GQA group and achieve equivalent-scope median wall latency no slower than native under the matched protocol. A Stage A failure or Implementation Correctness failure stops immediately; a Stage B speed failure stops before layer or full-model expansion. W4A16 local accuracy metrics are informational and never stop this speed-first experiment.

## Candidate architecture

- Use one `QHPI_RESOURCE_EXCLUSIVE` operator for one GQA group. Stage A first
  proves ordered HMX to HVX to HMX execution and visibility inside this one
  operator; failure stops for user discussion and does not trigger a three-op
  fallback.
- Run QK and AV on integer HMX. Pack dynamic Crouton U8 K and V into the HMX S8
  layout with HVX inside the core, once each per GQA group, and reuse each pack
  across both query heads. Packing cost remains inside the timed boundary.
- Keep one 64-KiB U8 score/probability buffer in VTCM for the GQA group. QK
  writes score, HVX performs scale, dynamic mask, and Softmax, then overwrites
  the same storage with probability before HMX AV. Online FlashAttention
  recurrence is outside the first candidate.
- Reproduce the baseline mask rule: calculate each row minimum, use
  `row_min - 20` for masked positions, then apply Softmax. Do not substitute a
  fixed masked code or silently exclude masked positions in this Experiment.
- Read per-layer qparams at graph construction and specialize one shared kernel
  through precomputed metadata. K/V zero-point 128 and probability encoding
  `(1/255, 0)` are checked fast-path predicates; no Layer-14 qparam may be
  treated as a model-wide constant.
- SIMD utility code from EXP-0009 may be reused, but the rejected E2Softmax
  mathematical reference and standalone scheduling contract are not reused as
  correctness authority.

## Staged execution

1. **Stage A — mixed-resource plumbing.** Prove a small in-graph
   HMX-to-HVX-to-HMX data path, ordered visibility, true integer HMX use, TCM
   placement, Core-Internal Zero DRAM, and Implementation Correctness.
2. **Stage B — one complete GQA group.** Implement the fixed layer-14 workload
   and compare Equivalent-Scope Wall Latency against the matching native QNN
   QK-to-Softmax-to-AV range. A slower median result stops expansion but still
   produces a valid negative micrograph result.
3. **Stage C — middle layer.** Only after Stage B passes, instantiate eight
   single-group fused cores for all 16 query heads and compare layer-scope wall
   latency. Do not replace them with one all-head custom operator.
4. **Stage D — full model.** Only after Stage C passes, integrate the 28-layer
   prefill path and report actual prefill throughput against the Selected W4A8
   Baseline and current W4A16 comparator. This does not automatically promote a
   baseline.

## Correctness and accuracy policy

- **Implementation Correctness is blocking.** A bit-exact host emulator defines
  the declared integer algorithm. Device Y and the correctness-only debug
  probability output must have zero byte mismatches, including mask, padding,
  and unused regions. A mismatch is an implementation defect and blocks valid
  performance evidence.
- **Accuracy Diagnostic is non-blocking.** Start from the same dequantized real
  layer-14 Q/K/V values, encode them separately for W4A16 and W4A8, and compare
  W4A16 native, W4A8 native, and W4A8 custom outputs under the same mask and
  cache range. Report NRMSE, cosine similarity, and maximum absolute error.
  Suggested indications are at most `1.05x` native-W4A8 NRMSE, at most `0.001`
  additional cosine loss, and at most one W4A8 output quantization step of
  additional maximum error. Exceeding them does not stop this speed-first
  Experiment.
- The debug artifact may expose probability only for correctness analysis. It
  is ineligible for zero-DRAM or performance claims. The formal performance
  artifact must not expose score or probability.

## Placement and performance evidence

- The formal fused core must report operator-attributed DRAM read/write `0/0`;
  score, probability, and dynamic workspace must never become DDR tensors.
- No spill/fill, CPU fallback, graph split, or explicit workspace graph output
  is permitted. Compile-time peak VTCM must stay within 8 MiB.
- Normal Q/K/V/mask/Y graph-boundary movement and persistent past-cache reads
  are outside core attribution, but must be identical and included in both
  candidate and native wall-time measurements.
- Candidate and native use the same device state, input/output placement,
  frequency policy, warm-up, repetitions, thermal acceptance, and runner. The
  primary local metric is median device wall latency; work and active cycles are
  explanatory only.
- True HMX evidence is required for both QK and AV through Optrace resource
  attribution and DSP instruction evidence.
